## Design Specificity Verdict

Интерфейс **категорийно взаимозаменяем**. В продукте есть сильные собственные сущности — memory, capability policy, budgets, subagents, research и run inspector, — но визуальный язык почти не использует их. Нейтральные shadcn-подобные токены, системный шрифт, чёрная primary-кнопка, серые карточки и обычная chat/admin-композиция могут принадлежать любому AI-клиенту.

**LLM-оценка:** продуктовая специфика живёт в названиях и структурах данных, но не в композиции, характере или сценарии активации. Самый удачный авторский фрагмент — мобильный Chat settings sheet: режимы безопасности переведены в понятные последствия и собраны в уверенный, управляемый выбор.

**Детерминированный скан:** `detect.mjs` выполнен один раз по `frontend/src`, exit code 0, результат `[]`, 0 правил и 0 файлов. Это чистый механический результат, но в данном случае явный semantic false negative: скан не заметил перегруженную IA, опасное удаление, слабые recovery states и mobile overflow, подтверждённые живым интерфейсом.

**Visual overlays:** надёжного пользовательского overlay нет. Mutable preflight был заблокирован browser security policy: title не изменился, marker-script count остался 0. Поэтому `detect.js` не внедрялся; fallback — DOM snapshots и screenshots маршрутов `/`, `/memory`, `/analytics`, `/settings`.

## Overall Impression

Основа аккуратная и функциональная, но выглядит как техническая консоль для авторов системы, а не как уверенный продукт для работы с агентами. Главная возможность — перестроить интерфейс вокруг пользовательских целей и сделать Chat безусловным центром, а сложные подсистемы — прогрессивно раскрываемыми.

## What's Working

1. **Mobile Chat settings** удачно объясняет три режима безопасности через последствия: «подтверждать каждый tool call», «разрешить файлы, подтверждать code», «выполнять всё». Крупные строки и фиксированный Done дают ясный контроль.
2. **Мобильный shell сделан осознанно:** отдельные back/menu controls, 44px targets в app bar и закрытие drawer по Esc лучше, чем простое сжатие desktop sidebar.
3. **Memory и Analytics имеют понятный каркас:** summary cards, range controls, tabs, counts и явные empty states создают читаемую структуру даже при нейтральной стилистике.

## Cognitive Load

Нагрузка **высокая: 5 из 8 пунктов не пройдены**. Провалены single focus, chunking, visual hierarchy, minimal choices и progressive disclosure; пройдены grouping, one thing at a time и working-memory continuity.

Основные decision points выше лимита четырёх элементов:

- 10 равноправных разделов из `NAV_ITEMS`, плюс Chat, Projects и Conversations;
- мобильный drawer одновременно показывает системные разделы, New conversation, проекты и длинную историю;
- desktop composer постоянно показывает attachment, workspace, Build/Plan, permission mode, model и context;
- Settings содержит десятки tool permissions и capability gates без поиска, категорий и режима «только изменённые».

## Emotional Journey

Старт спокойный, но эмоционально плоский: empty state не показывает примеры задач и не объясняет силу harness. После создания диалога пользователь получает ещё один пустой canvas и длинную историю, поэтому activation ощущается административной. Пик — понятный mobile Chat settings sheet. Провалы доверия — мгновенное удаление, сырой MCP/WinError, мобильное обрезание Analytics/Settings и финалы вида `No data` без следующего шага.

## Priority Issues

### [P1] Навигация повторяет backend-архитектуру, а не цели пользователя

**Почему важно:** Memory, Wiki, Profiles, Analytics, Subagents, Deep Research, Tasks, Budgets, Inspector и Settings имеют одинаковый вес. Новичок должен сначала понять устройство системы.

**Исправление:** оставить 3–4 goal-based группы — Work, Knowledge, Automations, Operations; Chat/New conversation сделать доминирующим; диагностику и admin перенести во вторичный workspace или command palette; добавить поиск и recent/project grouping диалогов.

**Команда:** `$impeccable distill`

### [P1] Удаление диалога мгновенное и слишком легко нажимается

**Почему важно:** каждая строка имеет корзину, которая сразу вызывает delete; на мобильном она постоянно видна, и сам target около 14px. Потеря данных реальна и необратима.

**Исправление:** сделать Archive поведением по умолчанию; иначе — confirmation с названием диалога плюс Undo toast. Перенести destructive action в overflow и обеспечить target не меньше 44px. Accessible name должен включать название диалога.

**Команда:** `$impeccable harden`

### [P1] Важные мобильные поверхности не адаптированы

**Почему важно:** на 390×844 у Analytics обрезается icon/header, заголовок дублируется, range row сжимается; Settings имеет horizontal overflow и обрезанные provider controls; 32px Send конфликтует со scrollbar textarea.

**Исправление:** убрать повтор page H1 на мобильном, stack/wrap header controls, сделать responsive padding, запретить page-level horizontal overflow и довести composer actions до 44px.

**Команда:** `$impeccable adapt`

### [P2] Продукт визуально generic, а активация инертна

**Почему важно:** пустой canvas и Sparkles не объясняют, чем harness отличается и какие результаты даёт.

**Исправление:** создать authored first-run canvas с 3–4 реальными starting intents, recent/project context и узнаваемым мотивом orchestration/run state вместо универсального sparkle.

**Команда:** `$impeccable onboard`

### [P2] Advanced Settings трудно проверять и чинить

**Почему важно:** длинная плоская матрица, внутренние имена, cycle-on-click и сырой WinError мешают понять «что отличается от default?» и как восстановиться.

**Исправление:** категории и поиск, changed-only, reset per section, итог изменений перед Save и человекочитаемые recovery messages с diagnostics disclosure.

**Команда:** `$impeccable clarify`

## Persona Red Flags

### Alex — power user

- Сотни `Conversation #NNNN` без search, sort, pin, recent filter или bulk archive.
- Нет command palette для 10 системных разделов.
- Composer перегружен ускорителями, но не сообщает keyboard shortcuts.

### Sam — accessibility-dependent

- Мобильные delete targets намного меньше 44×44.
- Analytics bars — нефокусируемые `div`, детали доступны только через `title`.
- Повторяющиеся кнопки имеют accessible name только `Delete`, без названия диалога.
- Закрытый mobile drawer остаётся смонтирован как `role=dialog`; screen-reader isolation надо подтвердить отдельно.

### Casey — distracted mobile user

- Drawer превращается в стену из разделов, проектов, истории и destructive actions.
- Settings и Analytics переполняются по горизонтали.
- 32px Send мал для управления одной рукой.
- Хорошее исключение — Chat settings sheet с крупными строками и sticky Done.

## Minor Observations

- Мобильный app bar и H1 страницы повторяют одно и то же название.
- Analytics смешивает локали: `0,00 $`, даты `31.07.2026` и `98.1%`.
- Memory может показать `Active: 8` одновременно с нулём в выбранном scope без пояснения области подсчёта.
- `Compact`, `ctx —`, MCP и provider/model IDs семантически непрозрачны.
- Settings начинается с `Providers`, но не имеет page-level heading `Settings`.
- В Analytics большие панели заканчиваются `No data`, хотя KPI выше показывают накопленные вызовы и токены.

## Questions to Consider

1. Если Chat — дом продукта, почему десять внутренних подсистем имеют тот же навигационный вес, что работа пользователя?
2. Что останется узнаваемым именно как Cool AI Harness, если убрать все подписи?
3. Совместимо ли прямое delete с принципом durable execution, или archive/undo должен быть системным стандартом?
4. Должен ли Settings быть guided policy editor — Safe, Balanced, Autonomous плюс исключения — вместо плоской матрицы tool names?
5. Пустой диалог должен учить пользователя печатать или сразу показывать сильные исходы, которые способен дать harness?
