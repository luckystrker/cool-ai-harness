# M1 checkpoint — Rust protocol foundation and golden corpus

Status: **passed**

Date: 2026-08-31

Scope: canonical App Protocol foundation; no durable-state or runtime ownership cutover

## Outcome

The production Cargo workspace and `cool-protocol` crate now own App Protocol v1 commands, events,
envelopes, errors, cursor/page types, stream frames and the deterministic client reducer contract.
The existing Python/FastAPI and React application remain the active runtime and UI.

Python `AgentEvent` and research streams now canonicalize then losslessly project their existing
wire objects, so current Web/SSE/WebSocket/inspector/subagent consumers retain the same shape. This
is a compatibility bridge, not the M11 canonical Web transport cutover.

## Independent review

Independent reviewer: Raman (`independent_m0_review`), read-only inspection of the actual diff and
relevant untracked files. Five passes were required because every security/protocol/state fix was
reviewed again:

1. The first pass found client-controlled identity, incomplete runtime adapter coverage, incomplete
   stream inventory, weak sequence/idempotency/strict-envelope rules, single-platform CI and weak
   self-derived golden expectations. All were fixed with server authorization types, run-scoped
   adapters, a producer inventory, strict/idempotent replay, three-OS CI and independent expected
   states.
2. The second pass found incomplete approval terminal semantics, permissive tagged variants, a
   non-literal TypeScript v1 field and a no-op plan reducer. All were fixed and tested.
3. The third pass found approval collisions across conversations/runs, legacy Web authorization by
   model call ID, fail-open approval adapter defaults and a synthetic-only plan stream. The registry
   now keys server approval IDs and scopes actor/conversation/run; Web sends revision/run identity;
   the adapter fails closed; real plan execution emits `plan.created`; both reducers reject mixed
   plan IDs.
4. The fourth pass found failed plans replaying as running. `plan.progress` now has an explicit typed
   status, the actual failed execution path is tested, and a twelfth golden trace covers failure in
   Rust and TypeScript.
5. The final confirmation pass was clean: no actionable P0-P3 findings remained.

Accepted M1 residual risks:

- Approval tickets remain process-local and are lost on crash/restart; durable approval ownership is
  intentionally deferred to the Rust durable-run phases.
- Local mode derives the actor from conversation ownership. VPS/multi-user deployment still needs
  authenticated actor identity at the transport boundary before it is safe to expose remotely.
- Canonical envelopes are validated before legacy projection but are not yet the durable Web wire
  format; that cutover remains scheduled for M11.
- Arbitrary plugin/tool Python values are not exhaustively proven JSON-conformant, and JavaScript
  safe-integer limits for Rust `u64` values remain an explicit protocol constraint rather than a
  runtime check.
- The compatibility adapter still has a legacy fallback for missing plan IDs until old Python event
  producers are retired.
- Linux/macOS gates are configured in CI but only the Windows gates were executed locally for this
  checkpoint.
