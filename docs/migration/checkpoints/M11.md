# M11 checkpoint — Web cutover and compatibility workers

Status: **in progress (partial)**. The Rust HTTP/App Protocol facade and the
`cool serve` entrypoint are implemented and covered by tests. The React
cutover on top of the generated SDK, the Telegram adapter, the OpenCode Bun /
Python workers, the worker-review UI and the end-to-end packaging/upgrade
suite are **not** done, so the phase stays `[~]` and must not be treated as
complete.

Date: 2026-09-19

Scope of this increment: a browser-facing HTTP/SSE projection of the App
Protocol served by the Rust binary (`cool serve`), with the `local`/`server`
deployment profiles enforced fail-closed, canonical cursor/reconnect event
streaming, and a fetch/SSE transport added to the generated TypeScript SDK.

## Implemented

- New crate `crates/cool-http` (M11 §"Web cutover"):
  - `HttpFacade` wraps the existing `AppServer` without owning any agent,
    store or policy logic. Each browser identity is one in-process App
    Protocol connection: `AppServer::serve_io` runs over a `tokio::io::duplex`
    pipe and is driven by the existing `AppClient` (`ConnectionPool`), so the
    HTTP layer sees exactly the stdio/TUI/ACP request/response and live-event
    semantics. Connection creation runs outside the pool lock; the pool is
    capped at 128 live identities and refuses new ones with `503` instead of
    evicting a connection that could own a run.
  - `GET /api/health` — public liveness/phase/capabilities document.
  - `POST /api/rpc` — accepts the canonical `RpcRequest` and returns the
    canonical `ServerFrame` (`RpcSuccess`/`RpcFailure`) with the request id
    echoed, so no HTTP-specific business model is introduced. Only a parse
    failure or an unavailable protocol connection uses a small structured
    transport error; command errors stay canonical `RpcFailure`.
  - `GET /api/events?runId&afterSeq&limit` — SSE stream with canonical
    cursor/reconnect semantics: subscribe → durable catch-up via `run.events`
    → live tail filtered by `seq`, re-catch-up on `Lagged`, `Last-Event-ID`
    precedence over `afterSeq`, and `end` on terminal. Payloads are
    re-projected (a bare `EventEnvelope` for `run.event`, the protocol
    `StreamKeepalive`/`StreamEnd` payloads for keepalive/end), not the tagged
    `StreamFrame` enum. `limit` is clamped to the server-configured
    `event_page_limit` so the facade never requests a page the runtime rejects.
    A client that reconnects with a past cursor cannot double-apply an event.
    An unauthenticated request that would mint a brand-new identity is refused
    (`403 client_identity_required`) unless a token is configured, so a
    cross-site no-cors GET (no Origin, no SameSite cookie) cannot spawn
    connections.
  - Production React assets are served from `--assets` with an SPA
    `index.html` fallback (tower-http `ServeDir::fallback`); without assets
    the root returns a diagnostic placeholder.
- Deployment profiles (`crates/cool-http/src/auth.rs`), fail-closed at startup:
  - `local` (default): loopback-only peer enforcement, optional shared token,
    loopback Origin allowlist that is enforced whenever an Origin is present
    (reads and mutations), non-loopback bind refused without `--allow-remote`
    **and** a token. A present-but-unparseable Origin (`null`, empty, opaque)
    and duplicate `Origin` headers are rejected rather than treated as "no
    Origin"; IPv6 loopback origins (`http://[::1]:…`) are accepted.
  - `server`: token mandatory, `--tls-terminated`/`--trusted-proxy` boundary
    mandatory, `--public-url` mandatory, exact-Origin enforcement whenever an
    Origin is present plus a required Origin on mutations, `Secure` client
    cookie.
  - Token auth accepts `Authorization: Bearer`, `?token=` (for native
    `EventSource`) and a cookie, compared in constant time; client identities
    are generated, validated, and persisted in an HttpOnly `SameSite=Strict`
    `cool_client` cookie. A valid `x-cool-client` header wins, but an invalid
    header no longer shadows a valid cookie.
- `cool serve` CLI command (`crates/cool-cli`): `--data-dir`, `--bind`,
  `--port`, `--assets`, `--profile`, `--token`, `--public-url`,
  `--trusted-proxy`, `--tls-terminated`, `--allow-remote`, `--legacy-store`;
  reuses `build_server` so `--legacy-store` serves the typed legacy families.
  `cool doctor` now reports `phase: M11`, `webFacade`,
  `serveProfiles: ["local","server"]`.
- `sdk/typescript/src/http.ts`: `HttpTransport` (commands over `POST /api/rpc`)
  and `streamRunEvents` (async SSE iterator) implementing the existing
  `CoolTransport` contract. Both send the token via `Authorization`, never
  `?token=`, and the header documents that Node callers must reuse one
  `clientId` across a transport and its event stream. Typechecked by
  `npm run protocol:check`.

## Compatibility

- The App Protocol v1 surface, generated schema, golden traces, SDK method
  names and `plugins.lock.json` are unchanged; the facade only projects the
  existing protocol over HTTP/SSE.
- No Python or frontend runtime behavior changed: the FastAPI REST/WS backend
  is still the running production path until the React cutover lands. This
  increment is additive and opt-in via `cool serve`.

## Data and security

- The HTTP facade never opens SQLite directly: commands go through the same
  actor-scoped `AppServer` dispatch as other transports.
- Fail-closed ordering: profile validation happens before binding, so a
  misconfigured `server` deployment cannot start; request bodies are capped at
  the 1 MiB protocol frame limit; `local` refuses non-loopback peers, opaque
  origins, and cross-origin reads as well as mutations; `server` requires an
  exact Origin whenever one is present and a mandatory Origin on mutations.
- The connection-pool cap (`503` when full) bounds the resource cost of forged
  client identities; identity creation no longer serializes all clients behind
  one handshake, and an unauthenticated request that would mint a new identity
  is refused on the SSE endpoint (`403 client_identity_required`) unless a
  token is configured. A browser without the `cool_client` cookie cannot open
  a stream at all, which closes the cross-site no-cors GET path.
- No new secrets are logged or returned; `ServerConfig`'s secret-presence-only
  `Debug` is unchanged. No `unsafe` code (workspace forbids it).

## Independent review

First pass `m11_web_facade_review` (read-only, not the author) inspected the
full diff and untracked files, ran `cargo test -p cool-http -p cool-cli` and
clippy, and probed the built binary on loopback. Findings and resolutions:

1. **P1 — local CSRF bypass via `Origin: null`.** An unparseable/opaque Origin
   was treated like an absent Origin, so a sandboxed/`data:` page could POST to
   a tokenless local server. Fixed: `origin_allowed` rejects any
   present-but-invalid Origin and duplicate `Origin` headers; regression tests
   `opaque_and_duplicate_origins_are_rejected` and
   `opaque_origin_is_rejected_in_local_profile`.
2. **P2 — unauthenticated pool exhaustion, slots never released.** Accepted
   residual risk (below): the Origin fix removes the cross-site path, and a
   co-located process already has OS-user access. The cap is kept so exhaustion
   is at least bounded and visible.
3. **P2 — SDK identity is cookie-dependent; the Node/live-stream claim was
   overstated.** The SDK header now states Node callers must reuse one
   `clientId` across `HttpTransport` and `streamRunEvents`, since events are
   delivered to the connection that started the run.
4. **P2 — bearer token placed in the SSE URL.** Fixed in the SDK (sends
   `Authorization`); the facade keeps `?token=` only for native `EventSource`.
5. **P3 — duplicate `Display`/non-exhaustive match and dead old body** were
   introduced while adding `LimitReached`; fixed.
6. **P3 — constant-time compare returns early on length mismatch.** Kept:
   token length is not a meaningful secret for a ≥16-char high-entropy token,
   and length-independent comparison of unbounded inputs is not standard.
7. **P3 — IPv6 loopback origins rejected.** Fixed by stripping the
   `Uri` authority brackets before `IpAddr` parsing; test
   `ipv6_loopback_origin_is_allowed`.
8. **P3 — HTTP `limit` could exceed a configured page limit.** Fixed by
   clamping to `min(256, server.event_page_limit)`; test
   `sse_limit_is_clamped_to_the_server_page_limit` fails without the fix.
9. **P3 — live/Lagged/keepalive/Last-Event-ID/Lagged paths were untested.**
   Added `live_phase_streams_events_emitted_after_catch_up` (slow provider
   forces the live broadcast path) and
   `last_event_id_header_takes_precedence_over_after_seq`. `Lagged` re-catch-up
   remains logic-only (hard to trigger deterministically at this size).
10. **P3 — SSE `end`/`keepalive` payloads were ad hoc.** Now serialize the
    canonical `StreamEnd`/`StreamKeepalive` types.
11. **P3 — pool mutex held across `initialize().await`.** Fixed: creation and
    handshake run outside the lock; a racing duplicate is discarded before it
    owns a run.
12. **P3 — an invalid `x-cool-client` header shadowed a valid cookie.** Fixed
    by filtering the header before falling back to the cookie; test
    `invalid_client_header_does_not_rotate_the_cookie_identity`.
13. **P3 — `--tls-terminated` is only an acknowledgement.** Documented as
    deferred; no in-process TLS this increment.

Second pass `m11_web_facade_followup` (read-only, different reviewer) verified
the fixes and found:

- **P2 — cross-site pool exhaustion via `GET /api/events`.** The first pass
  only guarded mutations, so a cross-site page could still mint identities on
  the GET SSE endpoint (browsers omit the `SameSite=Strict` cookie on
  cross-site requests). Fixed: `origin_allowed` now validates a *present*
  Origin on reads too, and rejects userinfo-bearing origins
  (`http://evil@localhost/`). Tests
  `cross_site_reads_are_rejected_and_userinfo_origins_fail` and
  `cross_site_event_stream_is_rejected`.
- **P3 — the invalid-header/cookie test was claimed weak.** Rebutted with the
  pre-fix expression semantics: `header.or_else(cookie).filter(valid)` yields
  `None` when the header is invalid, so `is_new=true` and a `Set-Cookie` was
  emitted; the test asserts its absence, so it does fail pre-fix. Kept as-is.
- **P3 — keepalive/`end` payload shape was untested.** Added
  `routes::tests::canonical_stream_frame_payloads_serialize_as_expected` and
  `terminal_events_are_recognized`; the 15 s idle branch itself is not
  timing-tested.
- **P3 — SDK token-header placement had no runtime test.** Claim corrected:
  verified by inspection/typecheck only.
- **P3 — frames are re-projected, not wire-identical.** `run.event` carries a
  bare `EventEnvelope` and keepalive/end carry the `StreamKeepalive`/
  `StreamEnd` payloads rather than the tagged `StreamFrame` enum; the
  checkpoint now says "re-projected" instead of "canonical".
- **P3 — unused dependencies.** Removed `async-trait`, `cool-security`,
  `cool-store` from `crates/cool-http/Cargo.toml`.
- **P3 — missing `runId` used axum's default body.** Now returns the
  structured `missing_run_id` error (test `cross_site_event_stream_is_rejected`).
- **P3 — `router()` needs `ConnectInfo`.** Fixed: documented on
  `HttpFacade::router`.

Third pass `m11_web_facade_followup_2` (read-only) verified the second-pass
fixes and found the read-Origin check still insufficient:

- **P2 — Origin-less no-cors GET still minted a connection.** A browser sends
  no `Origin` on no-cors GETs (`<img>`/`<script>`/`no-cors` fetch) and
  `SameSite=Strict` withholds the cookie, so the request reached the SSE
  handler as a fresh identity and could consume pool slots. Fixed structurally:
  the SSE handler now refuses to create a connection for a newly minted,
  unauthenticated identity (`403 client_identity_required`) unless a token is
  configured; test `anonymous_event_stream_is_rejected`. The claim that the
  cross-site path is closed is now backed by this guard, not by Origin alone.
- **P3 — stale mutation-only wording / GET-specific `null`/duplicate tests /
  `router()` doc.** The mutation-only wording was corrected in the Implemented
  and Data/security sections; the shared `origin_allowed` parse/duplicate
  branches are method-independent; the `router()` doc was added.
- **P3 — token-bypass branch untested.** Added
  `token_authenticated_event_stream_may_mint_identity` (local + token: an
  identity-minting SSE request with `Authorization` must stream, not 403), so
  inverting the `!token_configured()` condition now fails the suite.
- **P3 — residual wording understated a loopback-origin page.** Corrected: a
  different local web origin (e.g. `http://localhost:3000`) can also mint via
  `POST /api/rpc`; this is the accepted tokenless-local single-user risk and is
  not remotely reachable.

The fourth read-only pass confirmed the guard order, the token bypass, the
cookie-established (non-minted) SSE path, and that `/api/rpc`/`/api/health` did
not regress; it reported no P0-P2 issues, and its three P3 documentation/test
nits are addressed above.

## Deferred (remaining M11 exit criteria)

- React UI cutover: `frontend/src/api/*` still targets the Python REST/WS
  backend. The generated SDK + `HttpTransport`/`streamRunEvents` are the
  intended boundary but `src/api` has not been rewired, and
  `useConversationStream` still uses WebSocket instead of the canonical SSE
  cursor. Until then, `npm run protocol:check`'s inventory still describes the
  Python facade.
- `server` profile operationalization for VPS + Telegram adapter (Mini App
  `initData` signature/freshness validation, actor/session mapping) and its
  forgery/replay/cross-user integration tests.
- OpenCode Bun compatibility worker; optional Python OCR/document/ML workers;
  worker permission review/status UI (the worker-status data already exists
  from M8 but has no web surface here).
- End-to-end packaging/upgrade tests for the single-binary + asset bundle and
  deleting/retiring the Python web server (M12).
- Graceful shutdown / draining of the HTTP facade and idle connection
  eviction.
- TLS termination in-process (currently only the boundary acknowledgement is
  modeled; TLS is expected at a trusted reverse proxy).

## Residual risks

- Each distinct `cool_client` identity holds a live protocol connection for
  the process lifetime. The pool is bounded at 128 and refuses new identities
  when full, but there is no idle eviction yet: a legitimate long-lived
  deployment with many browsers would need eviction with run-safety analysis,
  and (accepted) a local caller can occupy all 128 tokenless-local slots for
  the process lifetime. That caller can be a co-located process (which already
  has filesystem access) or, because `localhost` is itself a loopback origin,
  a *different local web app* (`http://localhost:3000`) whose `POST /api/rpc`
  mints identities. Non-loopback/opaque origins and anonymous SSE are refused,
  so this is not remotely reachable; it is the accepted cost of a tokenless
  single-user local default.
- The SSE stream cannot know locally that a run is already terminal when the
  requested cursor is already past the terminal seq, so it stays live and
  emits keepalives instead of a synthetic terminal frame. Clients that know
  the run finished should close the stream.
- `?token=` auth for `EventSource` places the token in the URL (and thus
  access logs); the `Secure` cookie path is preferred where a login flow can
  set it. Recorded here because the server profile currently has no login flow.
