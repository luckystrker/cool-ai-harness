# M12 checkpoint — Default cutover and Python removal

Status: **done** — implementation and gate evidence below; the legacy Python
server, its test/eval lane and the M0 spike were removed under
[ADR-0003](../adr/0003-remove-legacy-python-server.md) on 2026-09-27 (maintainer
directive; the §14.13 release-count wait was waived).

Date: 2026-09-26

## Implemented

- **Rust runtime is the default on every install path.** The production image
  (`Dockerfile`, `docker-compose.yml`) is a single `cool` binary + SPA bundle —
  no Python/Node/Bun in the runtime stage — and both README install paths
  (container, unified source) end at `cool serve`. No startup path invokes the
  Python server.
- **Python server removed from default startup.** The only remaining Python
  entrypoints are dev/eval/test tooling and the parked optional-worker lane
  (`docs/backlog/python-workers.md` — OCR/document/ML workers over the
  compatibility-worker protocol, never on the default install).
- **Deep-research executor in Rust** (`cool-app-server/src/research.rs`):
  five-stage pipeline (decompose → gather via researcher subagent runs →
  source collect → synthesize → cite) with Python's caps
  (`MAX_SOURCES_PER_SUBAGENT`, `MAX_TOTAL_SOURCES`, snippet/citation limits),
  `research.cancel` wired to the live pipeline via shared watch channels, a
  `ResearchLiveGuard` that can never leave a row `running` after a panic, and
  canonical `research.*` events on a per-run canonical stream.
- **Canonical run for research.** `research.create`/`research.rerun` start an
  *auxiliary* canonical run (`start_auxiliary_run` — not the session's active
  run, so a rerun on one conversation is not gated by `session_run_active`,
  matching Python's background-task semantics) and return `runtimeRunId`; the
  client streams progress with `streamRunEvents`. `run.cancel` and
  `research.cancel` land on the same cancel channel.
- **Blob transports on `cool serve`** (`cool-app-server/src/blobs.rs`,
  `cool-http` routes): artifact upload/download, memory export, research
  export (md/html locally; pdf/docx explicitly delegated to the optional
  Python worker lane).
- **Attachment prompts.** `session.prompt` now expands the pre-existing
  `ContentPart` `artifact`/`image` variants server-side (extracted text inlined,
  ownership checked against the session's conversation, ≤10 artifacts,
  images acknowledged but not vision-readable — recorded gap).
- **Executor-bound agent tools** (`cool-cli/src/executor_tools.rs`):
  `deep_research`, `spawn_subagent` (with `await_terminal` + parent-cancel
  propagation), `list_skills`/`use_skill`/`create_skill` — registered into the
  live registry after server build so the agent loop reaches the executors.
- **Parity items:** built-in default system prompt ported to
  `cool-agent/default_system_prompt.txt` (settings → file → built-in
  resolution kept), `seed_builtin_roles()` on writable stores only,
  `artifacts_dir` wired, `web_search`/`web_fetch` network tools
  (prior increment).
- **Frontend is fully canonical.** `streaming.ts` and `research.ts` lost the
  legacy SSE fallbacks; every `frontend/src/api` op is `sdk` / `static/blob` /
  `sse/stream` in `inventory.json` — zero `deferred` entries.
- **Docs.** README stack/install sections describe the Rust default;
  `docs/PLAN.md`, `AGENTS.md` updated; rollback release documented at
  `docs/migration/M12_ROLLBACK.md`; the legacy-server removal ADR is proposed
  at `docs/migration/adr/0003-remove-legacy-python-server.md`.
- **Legacy test disposition.** The deleted `backend/tests/README.md` recorded
  the mapping: the SPA-facing coverage this suite owned is replaced by the
  Rust suites (`cool-store` domain tests, `cool-app-server` surface tests,
  `legacy_surface.rs`, `cool-http`, `frontend/protocol-tests`); the pytest
  suite was removed with `backend/` when ADR-0003 was executed.

## Compatibility

- App Protocol v1 extended additively (`runtimeRunId`; `ResearchSource.confidence`
  retyped `f64 → string` to match the labels Python stores); old clients simply
  don't send the new fields.
- Python-owned `harness.db` still opens **read-only** under `cool serve
  --legacy-store`; `cool store adopt` remains the explicit ownership transfer.
- `session.steer` still rejects non-text parts (`unsupported_content_part`).
- pdf/docx research export returns the documented worker-delegation response;
  md/html are served directly.

## Data and security

- No new write paths outside `run_idempotent`/`idempotent` and the auxiliary
  run record (`research.start` scope, deduped by `research-exec:{id}` key).
- Artifact upload keeps Python's size caps and `tool_result` reservation;
  downloads are actor-scoped and conversation-checked.
- Image parts are acknowledged but their bytes never reach the model
  (no vision support) — no silent partial behavior.
- Prompt attachments are confined to the session's own conversation.

## Independent review

Round 1 (session `a02df71605564929a9a97c0e35998bed`): **request_changes** —
all gate deliverables pass; verdict driven by code defects.

Fixed:
- **High** — `snippet_around` sliced `&str` by byte offsets (panic on
  multibyte text, near-certain for the Russian-localized product); on the
  canonical path a panic left the aux `rust_runs` row `running` with no
  terminal event (subscribers hang), and `run_inline` had no
  `ResearchLiveGuard` at all. Now: char-window slicing, the pipeline runs in
  an isolated task with `run.failed("research_panic")` emitted on panic, and
  `run_inline` installs the guard.
- **Medium** — `blob_error_response` mapped `StoreError::NotFound` to 500;
  now 404 via `BlobError::is_not_found` (artifact download, research export,
  memory export — Python parity).
- **Medium** — `inline_md` dropped the tail after the last link, misparsed
  `[n]` citations next to links, and emitted `javascript:`/`data:` hrefs;
  rewritten to Python regex semantics (http/https only). `markdown_to_html`
  also skips table rows and supports h1..h6 like Python.
- **Lows** — queued research sub-questions no longer launch subagent rows
  after cancel; the scheduler honors `workflow_type="deep_research"` through
  the research executor instead of a plain agent turn;
  `expand_prompt_parts` fails closed when the session has no linked
  conversation; `upload` validates `kind` against `ARTIFACT_KINDS`, honors
  the multipart Content-Type, defaults the filename to `unnamed`, and
  returns 201; `ResearchSource.confidence` retyped `f64 → string` (Python
  stores labels); `SYSTEM_PROMPT_FILE` honored between the settings prompt
  and the built-in default.
- Deferred — the 40M-pixel image cap is a Python-side decode-time guard;
  the Rust path never decodes images (OCR/vision live on the Python worker
  lane), so it is recorded as not applicable rather than a gap.

Round 2 (same session, re-review of the fixes): **approve_with_comments** —
all gate deliverables and every round-1 finding verified resolved. Remaining
lows, all applied:

- Scheduled `deep_research` runs now attach the hidden `is_task`
  `[Task] name` conversation and pass `parent_task_run_id` into
  `run_inline`, matching `run_research_for_task`'s store link.
- A queued sub-question cancelled before its semaphore slot no longer emits

- Regression coverage for the round-1 fixes: `snippet_around` multibyte +
  off-boundary positions, `inline_md` tail/citation/non-http links, and
  `markdown_to_html` h5/table-row parity.
- The `spawn-subagent` idempotency comment now states the fresh-uuid intent
  instead of implying dedupe.
- Windows CI: `containment_unit_kills_descendants_with_the_child` is broken
  on main (added in `3fcce89`, never green there) — the Job Object test's
  `cmd /c` nested quoting never reached the blocking `ping`, and the
  sanitized empty environment cannot resolve `ping`. The test now writes a
  `ghost.cmd` helper and supplies `PATH`/`PATHEXT`/`SystemRoot`.
