## Implemented

- **Rust runtime is the default on every install path.** The production image
  (`Dockerfile`, `docker-compose.yml`) is a single `cool` binary + SPA bundle —
  no Python/Node/Bun in the runtime stage — and both README install paths
  (container, unified source) end at `cool serve`. No startup path invokes the
  Python server.
- **Python server removed from default startup.** The only remaining Python
  entrypoints are dev/eval/test tooling and the parked optional-worker lane
  (`docs/backlog/python-workers.md` — OCR/document/ML workers over the
  compatibility-worker protocol, never on the default install).
- **Deep-research executor in Rust** (`cool-app-server/src/research.rs`):
  five-stage pipeline (decompose → gather via researcher subagent runs →
  source collect → synthesize → cite) with Python's caps
  (`MAX_SOURCES_PER_SUBAGENT`, `MAX_TOTAL_SOURCES`, snippet/citation limits),
  `research.cancel` wired to the live pipeline via shared watch channels, a
  `ResearchLiveGuard` that can never leave a row `running` after a panic, and
  canonical `research.*` events on a per-run canonical stream.
- **Canonical run for research.** `research.create`/`research.rerun` start an
  *auxiliary* canonical run (`start_auxiliary_run` — not the session's active
  run, so a rerun on one conversation is not gated by `session_run_active`,
  matching Python's background-task semantics) and return `runtimeRunId`; the
  client streams progress with `streamRunEvents`. `run.cancel` and
  `research.cancel` land on the same cancel channel.
- **Blob transports on `cool serve`** (`cool-app-server/src/blobs.rs`,
  `cool-http` routes): artifact upload/download, memory export, research
  export (md/html locally; pdf/docx explicitly delegated to the optional
  Python worker lane).
- **Attachment prompts.** `ContentPart` gained `artifact`/`image` variants;
  `session.prompt` expands them server-side (extracted text inlined,
  ownership checked against the session's conversation, ≤10 artifacts,
  images acknowledged but not vision-readable — recorded gap).
- **Executor-bound agent tools** (`cool-cli/src/executor_tools.rs`):
  `deep_research`, `spawn_subagent` (with `await_terminal` + parent-cancel
  propagation), `list_skills`/`use_skill`/`create_skill` — registered into the
  live registry after server build so the agent loop reaches the executors.
- **Parity items:** built-in default system prompt ported to
  `cool-agent/default_system_prompt.txt` (settings → file → built-in
  resolution kept), `seed_builtin_roles()` on writable stores only,
  `artifacts_dir` wired, `web_search`/`web_fetch` network tools
  (prior increment).
- **Frontend is fully canonical.** `streaming.ts` and `research.ts` lost the
  legacy SSE fallbacks; every `frontend/src/api` op is `sdk` / `static/blob` /
  `sse/stream` in `inventory.json` — zero `deferred` entries.
- **Docs.** README stack/install sections describe the Rust default;
  `docs/PLAN.md`, `AGENTS.md` updated; rollback release documented at
  `docs/migration/M12_ROLLBACK.md`; the legacy-server removal ADR is proposed
  at `docs/migration/adr/0003-remove-legacy-python-server.md`.
- **Legacy test disposition.** `backend/tests/README.md` records the mapping:
  the SPA-facing coverage this suite owned is replaced by the Rust suites
  (`cool-store` domain tests, `cool-app-server` surface tests,
  `legacy_surface.rs`, `cool-http`, `frontend/protocol-tests`); the pytest
  suite remains the legacy lane's regression net until ADR-0003 removes it.

## Compatibility

- App Protocol v1 extended additively (`ContentPart` variants, `runtimeRunId`);
  old clients simply don't send the new parts.
- Python-owned `harness.db` still opens **read-only** under `cool serve
  --legacy-store`; `cool store adopt` remains the explicit ownership transfer.
- `session.steer` still rejects non-text parts (`unsupported_content_part`).
- pdf/docx research export returns the documented worker-delegation response;
  md/html are served directly.

## Data and security

- No new write paths outside `run_idempotent`/`idempotent` and the auxiliary
  run record (`research.start` scope, deduped by `research-exec:{id}` key).
- Artifact upload keeps Python's size caps and `tool_result` reservation;
  downloads are actor-scoped and conversation-checked.
- Image parts are acknowledged but their bytes never reach the model
  (no vision support) — no silent partial behavior.
- Prompt attachments are confined to the session's own conversation.

## Deferred

- `image_analyze` / real vision parts — the Rust `Message` type is text-only;
  tracked for the optional-worker lane.
- pdf/docx research export bytes — optional Python worker
  (`docs/backlog/python-workers.md`).
- Legacy server deletion — ADR-0003, gated on two stable Rust-default
  releases.
- "Two consecutive releases without Python rollback" is a release-time
  criterion tracked in the release log, not a code gate.
- Telegram adapter / `server`-profile operationalization — parked per M11.
