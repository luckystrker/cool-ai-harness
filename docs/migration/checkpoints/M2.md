# M2 checkpoint — unified delivery of the current application

Status: **passed**

Date: 2026-09-01

Scope: one production package for the current React/Python runtime; no Rust runtime ownership
cutover and no VPS/multi-user security claim

## Outcome

The current application now has one release image, one `cool serve` entrypoint and one same-origin
port for the React UI, HTTP API, SSE and WebSocket transports. Source and packaged runs share stable
configuration and mutable-state paths that later Rust binaries must preserve.

Local/single-user remains the supported profile. M2 deliberately does not treat `API_TOKEN` as Web
authentication, expose Compose beyond loopback, or auto-stamp an unversioned development database.

## Deliverables

- Root multi-stage `Dockerfile`: reproducible React build plus Python runtime, bundled builtin skills,
  Chromium/Tesseract/Git runtime dependencies, non-root UID 10001 and persistent `/var/lib/cool`.
- One-service `docker-compose.yml` with one loopback port and one named state volume.
- Stable `cool serve` CLI with source and packaged defaults.
- Unified `COOL_HOME`, config, data, workspace, skill, artifact and frontend path contract.
- Public same-origin SPA and `/api/health`; API compatibility token remains scoped to direct API
  clients and is not presented as a server authentication profile.
- CI image smoke for `/`, `/api/health`, non-root execution, builtin skills, Git, SSE and WebSocket.
- [Packaging contract](../M2_PACKAGING_CONTRACT.md) defining the compatibility boundary for the Rust
  cutover and the limits of local, VPS and Telegram profiles.
- Project Definition of Done now requires an independent read-only review after implementation and
  another pass after high-risk review-driven fixes.

## Verification

- Backend: Ruff passed; mypy passed for 154 source files; packaging/MCP suite passed 41 tests;
  deterministic eval gate passed 23/23 scenarios; the full suite passed all 800 tests. One existing
  cancellation test exposed a fixed-sleep race during the gate; it was changed to synchronize on
  active-run registration and then passed five consecutive targeted runs before the full rerun.
- Frontend: the generated-protocol check replayed 12 traces; oxlint passed with three pre-existing
  Fast Refresh warnings; the TypeScript/Vite production build passed.
- Packaging: `docker compose config --quiet` passed. A source-process live smoke served the built SPA
  and health endpoint from one port. TestClient exercised real SSE and WebSocket endpoints.
- Diff/metadata: CI YAML parsed successfully and `git diff --check` passed.

The local Docker build was attempted and reached the dependency/browser installation layer, but a
Playwright CDN timeout followed by an unavailable local Docker daemon prevented a completed local
image run. The package job therefore remains CI-only image evidence, exactly as permitted by the
repository gate when no local daemon is available; this checkpoint does not claim a local image
build passed.

## Independent review

Independent reviewer: Raman (`independent_m0_review`), read-only inspection of the actual diff and
untracked files. Four review rounds were used:

1. The first pass found invalid comma-form CORS parsing, unsafe handling of legacy unversioned data,
   token-protected SPA/health, missing builtin skills, Compose database override, legacy relative
   SQLite path drift and incomplete image transport smoke. These were fixed and covered by tests.
2. The second pass rejected schema-shape-based automatic stamping, found missing Git and brittle/
   unbounded CI transport checks. Production now fails closed on any unversioned application DB;
   Git is installed and smoke-tested; SSE JSON is parsed and WebSocket has a timeout.
3. The third pass found only a Compose path-override documentation mismatch and checkpoint status.
   Compose's intentionally fixed persisted layout is now explicit in `.env.example`, Compose and the
   contract; the checkpoint and roadmap were synchronized after the gates.
4. The final confirmation pass was clean: no actionable P0-P3 findings remained.

Accepted M2 residual risks:

- The release image has not completed a local build/run on this host; CI is the authoritative image
  build and container smoke until Docker Desktop is healthy again.
- Existing unversioned development database data has no automatic M2 import path. Startup refuses
  it without stamping or modifying it; users must retain the source installation and backup.
- Existing named-volume restart/persistence is structurally configured but lacks a separate local
  end-to-end restart test because the Docker daemon is unavailable.
- VPS authentication, trusted-proxy/TLS policy, rate limits, multi-user actor identity and Telegram
  `initData` validation remain later-phase work and are not safe deployment claims in M2.
