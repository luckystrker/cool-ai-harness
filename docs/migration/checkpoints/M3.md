# M3 checkpoint — standard plugin contract

Status: **passed**

Date: 2026-09-01

Scope: declarative plugin contract and lifecycle on the current Python runtime. Rust ownership of
the store/runtime, hook execution supervision, executable vendor adapters and multi-user/VPS
authorization remain later migration phases.

## Outcome

M3 establishes Agent Plugins 1.0 as the Tier-1 package contract and projects existing Cool skills
through strict Agent Skills validation. Portable bundles can declare skills, stdio/Streamable HTTP
MCP servers and canonical Cool hooks without Python callbacks or dynamic libraries.

The local store supports local-directory and commit-pinned Git install/update, an atomic lockfile,
content-addressed immutable installations, separate persistent data roots and explicit lifecycle
commands. Install and update are disabled by default. Runtime dependencies and required
capabilities are visible before enable; startup loads only enabled bundles whose lock/path/content
integrity still passes.

## Deliverables

- Strict Agent Plugins 1.0 manifest/MCP schemas and Agent Skills frontmatter validation.
- Component-level diagnostics so an invalid skill/MCP/hook does not hide healthy siblings.
- Canonical hook declarations with source/definition/capability trust hashes.
- `cool plugin install|update|list|enable|disable|remove|validate|doctor`.
- Atomic typed lockfile with source, revision, content hash, runtime dependencies, capabilities,
  install root and persistent data root.
- Full-SHA Git pinning and checkout verification; shell-free subprocess invocation.
- Runtime projection into the existing Skill and MCP registries with collision-safe policy and
  provider-safe MCP tool names.
- Representative portable, partial, Codex, Claude and manifestless Claude fixtures with semantic
  transformed/ignored/unsafe diagnostics.
- [Compatibility matrix](../M3_PLUGIN_COMPATIBILITY.md) and
  [supply-chain threat model](../M3_PLUGIN_THREAT_MODEL.md).

## Independent review

Independent reviewer: `m3_independent_review`, read-only inspection of the actual working-tree diff
and every relevant untracked fixture/document. Four review-driven rounds were completed:

1. Initial review found immediate activation, permissive Agent Skills, sibling-deletion lockfile
   redirection, disabled-plugin update activation, Windows reparse traversal, silent registry
   collisions, provider-invalid MCP names, generated-header priority and incomplete Tier-2 layouts.
2. The next pass confirmed those fixes and found truthy non-boolean `enabled`, vendor-manifest
   junction traversal, incomplete execute/network preview and whitespace-only Skill metadata.
3. The focused pass confirmed those fixes and found a hook-only runtime dependency omitted from
   preview.
4. The final pass was clean: no actionable P0-P3 findings remained.

Accepted M3 residual risks:

- The local JSON lockfile has atomic replacement but no multi-process writer lock. Concurrent
  lifecycle writers are unsupported until the Rust store adds an OS-level lock.
- Content hashes detect drift but are not publisher signatures or transparency-log proofs.
- Bare runtime dependencies are visible but not resolved to immutable package checksums; managed
  dependency acquisition belongs to M8.
- Hooks are declarations only in M3. Execution supervision, durable approvals/audit and capability
  enforcement remain M8 work.
- Codex/Claude executable semantics remain diagnostic-only until their adapters preserve security
  meaning. This is intentionally not silent compatibility.
- M3 remains local/single-user. It does not authorize public VPS or Telegram exposure.
