# M6 checkpoint — Durable state and security kernel

Status: **passed**

Date: 2026-09-01

Scope: single-local-core durable invariants, security primitives and worker supervision. The Rust
agent loop, trusted tool execution, concrete MCP/plugin workers and existing Python-store cutover
remain M7, M8 and M10.

## Outcome

The Rust App Server now persists its session/run lifecycle and canonical event stream in a
namespaced SQLite store, recovers interrupted work deterministically, and exposes durable approval
resolution. New `cool-security` and `cool-core` crates establish the policy, confinement, secret,
encryption and supervised-process foundations required before M7 may execute providers or tools.

## Deliverables

- `cool-state`: versioned `rust_*` SQLite schema for sessions, runs, events, idempotency,
  cancellation, approvals/audit, budgets, artifact references and worker generations.
- Transactional state transitions, auto-sequenced append-only events and replay-derived run state.
- Atomic terminal cancellation, approval compare-and-set and integer budget reservations under
  contention.
- Restart recovery that emits one canonical `run.failed` event without replaying side effects.
- `cool-security`: narrowing capability policies, confined workspace paths, SSRF/DNS-pinning
  policy, recursive secret filtering and Python-compatible versioned Fernet storage.
- `cool-core`: real child-process kill/restart supervision with durable generations and sanitized,
  allowlisted environments.
- Durable App Server/CLI wiring through `COOL_DATA_DIR` or `--data-dir`, with protocol-generated
  approval-resolution types shared by Rust and TypeScript.
- M6 ownership, schema coexistence and recovery design in
  [`M6_DURABLE_SECURITY_KERNEL.md`](../M6_DURABLE_SECURITY_KERNEL.md).

## Exit-criteria evidence

| Criterion | Evidence |
|---|---|
| Invalid transitions fail before side effects | `cool-state` tests assert unchanged event history and projection after an illegal transition. |
| Approval and budget races are atomic | Real threaded contention proves one approval resolver wins and budget counters never exceed the configured limit. |
| Cancellation cannot race completion into two terminal outcomes | Both outcomes contend through immediate SQLite transactions; the race test proves exactly one terminal event commits. |
| Core and App Server restart preserve unambiguous state | Incomplete runs recover once to `run.failed`; replay after a fresh App Server reconstructs the same terminal state. |
| Event replay is inspector source of truth | Replay derives the projection from ordered canonical events and rejects sequence gaps or cached-state divergence. |
| Critical security paths are covered | Capability narrowing, path escape/reparse rejection, public-address DNS pinning, redirect recheck, environment filtering and Python Fernet parity all have executable tests. |
| Worker lifecycle is real and durable | Tests spawn actual child processes, verify secret-free environments, wait for termination and prove monotonically increasing restart generations. |

There are no skipped critical M6 tests.

## Independent review

Independent reviewer: `m6_independent_review`, read-only inspection of the actual diff and relevant
untracked files. Review-driven passes found and resolved:

1. worker environment sanitization was not connected to process spawning and omitted common cloud
   credential names;
2. accepted cancellation could be acknowledged before durable terminal state and race completion;
3. failed worker termination could discard the only child handle;
4. cancellation validation reordered idempotency conflict behavior;
5. authorization identity and canonical event provenance were conflated;
6. MPL-2.0 was globally allowed instead of scoped to the `fernet` dependency;
7. one final Clippy `collapsible_if` warning blocked the required gate.

All findings were fixed. The final post-checkpoint pass was **clean**, with no actionable P0-P3
findings. The reviewer confirmed the security, cancellation-race, provenance, worker-lifecycle,
SSRF and license-scope fixes, inspected the checkpoint/status update, and verified
`git diff --check`.

## Residual boundaries

- Rust still emits the deterministic echo sequence; provider routing, agent execution and trusted
  tools remain fail-closed until M7.
- Rust uses a separate database with namespaced tables. It does not dual-write or assume ownership
  of existing Python SQLModel tables; backup/restore and data cutover belong to M10.
- One local core process is the supported ownership model. Cross-process leases and authenticated
  remote identities belong to M11.
- Artifact rows are validated references; content storage and legacy migration remain M10.
- SSRF/DNS results are policy primitives, not an HTTP client implementation; M7 must consume the
  pinned result and recheck every redirect.
- M8 owns concrete MCP/plugin worker protocols, health checks and stronger process isolation.
- Linux and macOS remain represented by CI; only Windows execution was verified locally.
- `ts-rs` still warns that it does not interpret Serde `deny_unknown_fields`; Serde and generated
  schema strictness remain covered independently.
