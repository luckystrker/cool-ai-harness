# M7 checkpoint — Agent loop and trusted tool runtime

Status: **passed**

Date: 2026-09-02

Scope: provider-neutral Rust agent execution, baseline OpenAI-compatible streaming, durable
conversation history, trusted built-in tools, approvals, cancellation, planning, subagents and
Python fallback boundary. Executable MCP/plugins/hooks remain M8; full CLI/TUI/ACP cutover remains
M9; Python store/background and Web/API cutovers remain M10-M11.

## Outcome

Production App Server prompts now run through `cool-agent` instead of the M5/M6 echo path. The
runtime owns provider streaming, retry, per-turn usage completeness, durable budget reservation,
tool policy/approval/dispatch, parallel batches, cancellation and canonical history. The durable
event log remains the sole history source and every requested tool has a terminal result before the
run terminal event, including explicit cancellation, disconnect and restart recovery.

## Deliverables

- `cool-agent`: provider-neutral messages and `ModelDriver`, streamed Rust agent loop, retries,
  cancellation, usage/budget guards, compaction, project instructions, planning and subagents.
- In-process OpenAI-compatible HTTP/SSE driver with rustls, DNS pinning, redirect denial, bounded
  response/time, fragmented tool-call assembly, split-UTF-8 safety and usage-trailer handling.
- Explicit loopback-only support for local OpenAI-compatible servers without weakening private or
  link-local SSRF policy.
- Trusted registry for confined file read/list/write, planning, git/shell launch boundaries and a
  preconfigured Python fallback adapter. Arbitrary host processes are fail-closed in production
  unless an embedding explicitly opts into the documented trusted-host launcher.
- Durable secret masking for direct store callers, App Server events, messages, tool arguments and
  approval previews while preserving original in-memory values for the current execution.
- Atomic pending-tool closure before `run.cancelled`/`run.failed` on client cancel, internal
  transport failure and restart recovery.
- Durable approval reconciliation that cannot lose a resolution between ticket commit and waiter
  registration.
- Operational `cool run`, configured App Server provider selection and an updated TypeScript stdio
  sample using the M7 five-event chat sequence.
- Design and threat-boundary record in [`M7_AGENT_RUNTIME.md`](../M7_AGENT_RUNTIME.md).

## Independent review

Independent reviewer: `m6_independent_review`, reused as a read-only reviewer that did not author
M7. The reviewer inspected the actual diff and untracked files across four passes. Findings fixed:

1. cancel/recovery and transport-failure paths could leave orphan assistant tool calls;
2. OpenAI usage trailers were lost and App Server did not reserve durable usage;
3. approval resolution had a lost-wakeup window;
4. arbitrary host process execution was incorrectly presented as a production sandbox;
5. durable messages/tool/approval payloads could retain secrets;
6. SSE chunk decoding could corrupt split UTF-8;
7. project instructions were unbounded/unconfined and loopback policy also admitted public DNS;
8. deterministic evals did not assert exact partial-batch completion;
9. later-turn missing usage or unknown cost could bypass configured budget limits;
10. internal cancellation ignored durable results and did not publish closure/terminal events.

All findings were fixed and affected checks rerun. The final pass was **clean**, with no actionable
P0-P3 findings. The reviewer confirmed cancellation/event ordering, sticky cost completeness,
approval reconciliation, durable masking, production process fail-closed behavior and the accepted
residual boundary below.

## Residual boundaries

- File tools reject absolute/parent escape and existing symlink/reparse traversal and revalidate
  immediately before I/O, but do not yet use handle-relative filesystem capabilities. Concurrent
  path replacement by a separate same-user process is outside the M7 single-local-core threat model
  and is an explicit M8 isolated-worker hardening item.
- Production host-process execution remains disabled until an OS-isolated launcher is configured;
  trusted-host launcher tests prove only lifecycle, environment and output bounds.
- The baseline provider does not calculate vendor/model pricing. Token accounting is durable; an
  explicitly configured cost ceiling fails closed when provider cost is unknown.
- Anthropic-native parity and provider/extension workers remain later migration work according to
  the M0 provider inventory and M8 boundary.
- Rust still uses its namespaced migration database; Python data ownership/cutover remains M10.
- M4 still requires real external ACP-client acceptance and is not reclassified by M7.
- Linux and macOS remain CI evidence; local execution was Windows.
- `ts-rs` continues to warn that it does not interpret Serde `deny_unknown_fields`; Serde and
  generated schema strictness remain covered independently.
