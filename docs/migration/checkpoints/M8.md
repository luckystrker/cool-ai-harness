# M8 checkpoint — MCP, plugins, hooks and workers

Status: **passed**

Date: 2026-09-02

Scope: Rust ownership of declarative plugin loading, MCP clients/tool projection, trusted hook
execution and generic compatibility workers. CLI/TUI and ACP cutover remain M9; background/store
parity and Web cutover remain M10-M11.

## Implemented

- New `cool-extensions` workspace crate with strict portable/vendor plugin discovery, deterministic
  content/trust hashes, Agent Skills parsing and component-isolated diagnostics.
- Backward-compatible, Python-hash-compatible M3 lockfile migration, integrity/containment checks
  and separate fail-closed hook review state that does not mutate the Python-owned lock schema.
- MCP stdio and Streamable HTTP clients with initialization/session lifecycle, DNS pinning,
  proxy/redirect denial, incremental long-lived SSE, bounded I/O/time and an explicit external
  OAuth boundary; HTTP carries the negotiated version and safely reinitializes after session 404.
- MCP tool projection into the M7 registry under namespaced collision-safe identities and a
  conservative all-capabilities approval policy plus core-owned enabled/disabled tool policy.
- Command/MCP hook engine with match/order declarations, exact trust review, policy narrowing,
  secret masking, bounded child processes and append-only audit.
- Generic versioned JSON-lines worker protocol plus supervised Codex/Claude request adapters,
  capability negotiation, deadlines, cancellation, structured errors, heartbeat and bounded
  messages. Side effects require idempotency; a crash restarts the worker and reports unknown
  outcome without replaying the request.
- Canonical `plugin.status` App Protocol event/reducer state, M8 `cool doctor`, and
  `cool plugin doctor <path>` diagnostics.
- App Server startup loads intact enabled M3 bundles and dispatches all M3 lifecycle hook names;
  bundle/server/worker and non-terminal hook failures emit status without removing built-in tools
  or terminating the core. Terminal-hook results remain in the masked audit because terminal state
  is made durable before those side effects.

## Compatibility

M3 lock version, install/data locations and content hashes remain readable. M7 built-in tool
behavior is unchanged; the registry extension API rejects duplicates. M4 remains pending only on
real external ACP-client acceptance and is not reclassified by M8.

## Data and security

Plugin-controlled executables never enter the Rust process. URL/path/environment/header validation,
DNS pinning, bounded output, child reaping, exact review hashes and policy intersection are enforced
before side effects. Hook audit output is secret-masked.
