# M9 checkpoint — Rust CLI/TUI and ACP cutover

Status: **passed**

Date: 2026-09-17

Scope: Rust CLI commands from section 7.1, the Ratatui TUI MVP, the App Protocol additions the TUI
and ACP need, and the ACP v1 adapter moved from the Python runtime to the Rust trusted core. Web
serving, background/store parity and compatibility workers remain M10-M11.

## Implemented

- New `cool-protocol` command families: `session.list`, `session.history`, `session.fork`,
  `session.steer`, `status.get`, plus their result types and generated schema/TypeScript artifacts.
- `cool-state`: actor-scoped session listing, history-preserving `fork_session` (new event ids,
  sequential `seq`, `causation_id` provenance, source session untouched) and durably idempotent
  `steer_run` that only accepts active runs.
- `cool-agent`: `EventSink::drain_steers` (default no-op) folded into history at each iteration
  boundary before compaction/model requests.
- `cool-app-server`: dispatch for the new commands, bounded history projection, `status.get`
  delegation to `RunLifecycle::status`, steer delivery that never re-delivers the run's own prompt,
  and a reusable `AppClient` protocol client with transport-close semantics.
- New `cool-tui` crate: Ratatui MVP (transcript, streaming content/reasoning, tool lifecycle, plan
  progress, approvals, sessions picker, slash commands, status line) driven by the shared canonical
  reducer, with a terminal-generic event loop.
- New `cool-acp` crate: ACP v1 stdio server over the Rust core (initialize, new/load/prompt/cancel,
  permission projection, bounded frames, request draining on shutdown).
- `cool-extensions`: M3-compatible `install_local`/`install_git`, `set_enabled`, status snapshot and
  MCP server listing accessors.
- `cool-cli`: `cool` (TUI), `cool acp`, `cool plugin install/list/validate/doctor`, `cool mcp list`,
  `cool hooks list`, M9 `doctor`; `cool` fails closed without an interactive terminal.

## Compatibility

- The App Protocol stays v1: new optional commands are additive; existing commands, envelopes and
  event shapes are unchanged. Generated schema/TypeScript were regenerated in the same change.
- The M3 `plugins.lock.json` version-1 document remains the shared format. Rust now writes it for
  `cool plugin install` (same field names, content-addressed `installations/<name>/<hash>` and
  `data/<name>` bindings); the Python lifecycle can still read it. Concurrent Python/Rust lifecycle
  writes are not supported and are not part of the M9 runtime path.
- ACP keeps the M4 pinned v1 contract; ACP v2 adoption remains an explicit future contract change.

## Data and security

- Steer writes are secret-masked before persistence and reject non-text content parts. A steer that
  races the terminal event stays durable for the session's next turn but may no longer reach the
  current run's model request; the client-side active-run check narrows that window.
- Fork copies only history-relevant events under the same actor, keeps the source immutable, never
  reuses event ids and preserves durable `(run, seq)` order instead of sorting by per-run `seq`.
- ACP fails closed for malformed permission responses, mismatched `cwd`, extra roots and
  client-supplied MCP servers; approvals keep their revision and idempotency semantics in the core.
  If the live event buffer lags, the adapter recovers the dropped range from `run.events` paging.
- `session.history` output is trimmed to the negotiated frame limit; an item that cannot fit any
  bounded frame yields `outbound_frame_too_large` instead of an empty page, and session labels are
  bounded to 200 characters so `session.list` cannot be made to exceed a frame.
- `cool plugin install` serializes with the same store write lock as `set_enabled`/hook review and
  writes through a unique temporary file, so concurrent CLI operations cannot lose lockfile entries.
- Git acquisition writes child output to files rather than unread pipes, eliminating the
  pipe-buffer deadlock window in the timed wait.
- Dropping an `AppClient` closes the transport and releases the reader task; run ownership and
  disconnect cancellation stay core-owned.

## Independent review

Independent reviewer: `m9_independent_review`, read-only inspection of the working-tree diff and
untracked files, plus targeted `cargo test`/`clippy`/`pytest`/`generate --check` runs. Verdict:
no P0; protocol/state semantics, test quality and security boundaries were "partially verified"
pending the findings below.

Actionable findings and resolutions:

1. **P1 — `session.fork` sorted merged history by the per-run `seq`.** Multi-run sessions were
   interleaved (run1.1, run2.1, run1.2 …) and never caught by single-run tests. Fixed by keeping
   the durable `(run rowid, seq)` query order; regression test
   `fork_preserves_multi_run_history_order_not_per_run_sequences`.
2. **P2 — ACP dropped events on broadcast lag and could hang the turn** if the terminal event fell
   into the dropped range. Fixed with durable `run.events` catch-up inside the prompt loop;
   regression test `broadcast_lag_recovers_from_the_durable_run_log` uses a 2-slot client buffer.
3. **P2 — `install_directory` bypassed the store write lock** and used a fixed temp lockfile name.
   Fixed: installs take the same write + file lock as enable/hook review and use a unique temporary
   file.
4. **P3 — `run_git` polled `try_wait` with unread stdout/stderr pipes.** Fixed by capturing git
   output to files.
5. **P3 — ACP bookkeeping growth and a dead field.** Fixed: finished request tasks are pruned,
   empty per-session permission sets are removed, `ActivePrompt.cancelled` deleted.
6. **P3 — Docs called `cool acp` "in-process"; the child process was not explicitly killed.** Fixed
   the documentation and added explicit child cleanup in `run_acp`.
7. **P3 — Unbounded session labels could make `session.list` fail as one oversized frame.** Fixed
   with a 200-character bound on `title`/`project_key` and a `label_too_long` error; test added.
8. **P3 — Windows symlink rejection test could skip silently.** The test now falls back to a
   privilege-free `mklink /J` junction and asserts that a real link was created.

The reviewer's "could not verify" items are recorded as residual risks below. A second independent
pass was requested for the review-driven protocol/state changes.

Second pass (`m9_independent_review_2`, same read-only method) verdicts: items 1, 3, 4, 5 and 7
fixed clean; items 2, 6 and 8 partially fixed, with three new issues that were then resolved:

1. **P2 — ACP re-projected events already covered by catch-up.** `Lagged` repositions the
   broadcast receiver to the oldest retained slot, so after a non-terminal catch-up the loop
   re-emitted up to the buffer size. Fixed with a `seq <= last_seq` guard; the lag test now asserts
   the exact ordered chunk concatenation (it fails both on the old `continue` and on duplicates).
2. **P3 — `spawn_app_server` could leak the child on post-spawn error paths.** Fixed with
   `kill_on_drop(true)` on the spawned command.
3. **P3 — the Windows link test could pass for the wrong reason, and root-link rejection was
   ineffective** because `install_directory` canonicalized the source before checking link-ness.
   Fixed: `PluginLoader::reject_links` checks the caller-supplied path before canonicalizing, and
   the test uses a fresh store root and asserts the rejection message contains "link".
4. **P3 — permission registration and cancellation used two locks**, so a concurrent
   `session/cancel` could miss a request mid-registration and delay the deny until the approval
   timeout. Fixed by collapsing the two maps into one session-keyed map guarded by a single lock;
   the new test `cancel_while_permission_is_pending_returns_cancelled_without_side_effects` proves
   the prompt returns `cancelled` promptly and the tool has no side effect.

- Plugin enable/disable/remove CLI subcommands and a full lifecycle UI: M10/M11 store parity.

## Residual risks

- Python-side read compatibility of Rust-written `plugins.lock.json` is established by identical
  field names plus the Rust lockfile-shape test, not by a cross-language round-trip test. Store
  ownership unification lands in M10.
- ACP permission timeout (300 s) itself is not shortened in a test; the cancel and malformed-object
  paths now have explicit coverage.
- `cool acp` acceptance against a real ACP client (Zed) is still pending; the adapter is exercised
  through the in-repo ACP client harness and the subprocess stdio smoke.
- `install_directory` can leave an orphan content-addressed directory if the lockfile write fails
  after the install tree is published; it is unreferenced, immutable and garbage-collected with M10
  store ownership. A large local install also holds the store lock across copy/hash work.
